## What is a Coordinate Frame?

A **coordinate frame** is a named reference system in which positions and orientations are measured. Every physical sensor, robot link, and world location has a frame associated with it.

Examples:
- `world` — a fixed point on the floor; robot position is expressed relative to this
- `base_link` — the center of the robot's body; sensor data is expressed in this frame first
- `camera_link` — the optical center of the camera; image-based measurements live here

When you have a measurement in one frame and need it in another (e.g., "the camera sees an object at 0.3 m forward — where is that in world coordinates?"), you need a **transform**: the translation + rotation that converts coordinates from one frame to another.

---

## The TF2 Tree

TF2 maintains a **tree** of transforms. Each node in the tree is a frame name. Each edge is a transform from a parent frame to a child frame. The tree has one root (usually `world` or `map`).

```
world
└── robot_base   (1.0 m forward, 0 m left, 0 rotation)
    └── camera_link  (0.1 m forward, 0.2 m up, -15° pitch)
```

To find the transform from `world` to `camera_link`, TF2 traverses the tree: `world → robot_base → camera_link`, composing the two transforms.

**`/tf` vs `/tf_static`:**

- `/tf_static` — transforms that never change (a rigidly mounted camera). Published once; stored by TF2 indefinitely.
- `/tf` — transforms that change over time (the robot moving through the world). Published repeatedly; TF2 keeps a time-indexed buffer.

Both use `tf2_msgs/msg/TFMessage`. The difference is in how TF2 stores and queries them.

## Publishing Static Transforms

The `tf2_ros` package provides `static_transform_publisher` — a node that publishes a single static transform on `/tf_static`.

**Humble syntax (named arguments — always use this form):**

```bash
ros2 run tf2_ros static_transform_publisher \
  --x 1.0 --y 0.0 --z 0.0 \
  --roll 0.0 --pitch 0.0 --yaw 0.0 \
  --frame-id world \
  --child-frame-id robot_base
```

This says: `robot_base` is located 1.0 m along the X axis of `world`, with no rotation.

The positional (ROS1-style) syntax does not work in Humble. Always use `--x`, `--y`, `--z`, `--roll`, `--pitch`, `--yaw`, `--frame-id`, `--child-frame-id`.

## Querying Transforms

### tf2_echo

`tf2_echo` looks up the transform between two frames and prints it continuously:

```bash
ros2 run tf2_ros tf2_echo world camera_link
```

Output:
```
At time 1704067200.000
- Translation: [1.100, 0.000, 0.200]
- Rotation: in Quaternion [0.000, -0.130, 0.000, 0.991]
```

The translation and rotation represent the composed transform from `world` to `camera_link` through the entire tree path.

### view_frames

`view_frames` generates a PDF showing the TF tree structure:

```bash
ros2 run tf2_tools view_frames
```

This creates `frames.pdf` in the **current working directory** (wherever you ran the command from). Open it with:

```bash
evince frames.pdf     # GNOME PDF viewer
xdg-open frames.pdf   # default PDF viewer
```

### rqt_tf_tree

`rqt_tf_tree` shows the same tree structure interactively in a GUI:

```bash
rqt_tf_tree
```

Note: `rqt_tf_tree` is in the package `ros-humble-rqt-tf-tree`, which is **separate** from `ros-humble-tf2-tools`. Both were installed in the section 4.1 install block. If `rqt_tf_tree` is not found, verify the install.

## Common TF Errors

| Error | Symptom | Diagnostic |
|---|---|---|
| Missing transform | "Could not find a connection between frame A and B in the buffer" | `view_frames` — frame absent from tree |
| Stale transform | "Lookup would require extrapolation N seconds into the past" | `tf2_echo A B` — timestamp gap between publishes |
| Disconnected tree | Two separate tree components, no path between them | `view_frames` — two separate graphs |
| Wrong direction | Transform present but position appears mirrored or inverted | `tf2_echo A B` then `tf2_echo B A` |
| use_sim_time mismatch | Extrapolation errors during bag playback | Confirm `use_sim_time` matches on all nodes |

## Exercise 1 — Build and Inspect a TF Tree

**Description**

In three separate terminals, publish a small tree:

**Terminal 1 — world → robot_base:**
```bash
ros2 run tf2_ros static_transform_publisher \
  --x 1.0 --y 0.0 --z 0.0 \
  --roll 0.0 --pitch 0.0 --yaw 0.0 \
  --frame-id world \
  --child-frame-id robot_base
```

**Terminal 2 — robot_base → camera_link:**
```bash
ros2 run tf2_ros static_transform_publisher \
  --x 0.1 --y 0.0 --z 0.2 \
  --roll 0.0 --pitch -0.262 --yaw 0.0 \
  --frame-id robot_base \
  --child-frame-id camera_link
```

(−0.262 radians ≈ −15 degrees pitch.)

Now inspect the tree:

1. `tf2_echo`:
   ```bash
   ros2 run tf2_ros tf2_echo world camera_link
   ```
   Note the composed translation (should be approximately x=1.1, z=0.2).

2. `view_frames`:
   ```bash
   ros2 run tf2_tools view_frames
   ```
   Open `frames.pdf`. Confirm it shows `world → robot_base → camera_link`.

3. `rqt_tf_tree`:
   ```bash
   rqt_tf_tree
   ```
   Confirm the same tree is visible in the GUI.

**Verification**

- `tf2_echo world camera_link` shows translation approximately [1.1, 0.0, 0.2] (exact values depend on yaw composition)
- `frames.pdf` shows three nodes connected in sequence
- `rqt_tf_tree` shows the same tree interactively

## Exercise 2 — Diagnose Four TF Failures

Each step below introduces one failure. Diagnose it using the tools you have, then explain the fix.

### Failure 1 — Missing frame

Kill Terminal 2 (`Ctrl+C` in the camera_link publisher). Then:

```bash
ros2 run tf2_ros tf2_echo world camera_link
```

Observe the "Could not find a connection" error. Run `view_frames` — `camera_link` is no longer in the tree. **Fix:** restart the camera_link publisher (Terminal 2).

### Failure 2 — Reversed parent/child

Restart Terminal 2 with `--frame-id` and `--child-frame-id` swapped:

```bash
ros2 run tf2_ros static_transform_publisher \
  --x 0.1 --y 0.0 --z 0.2 \
  --roll 0.0 --pitch -0.262 --yaw 0.0 \
  --frame-id camera_link \
  --child-frame-id robot_base
```

Now run `rqt_tf_tree`. What does the tree look like? The direction is reversed — `world → robot_base` is still present, but `camera_link → robot_base` creates a cycle or a separate root. **Diagnosis:** `rqt_tf_tree` shows wrong direction or a loop. **Fix:** swap `--frame-id` and `--child-frame-id` back.

### Failure 3 — Disconnected tree (extra root)

Restart Terminal 2 correctly. Then in **Terminal 3**, publish a transform with a different root:

```bash
ros2 run tf2_ros static_transform_publisher \
  --x 0.0 --y 0.0 --z 0.0 \
  --roll 0.0 --pitch 0.0 --yaw 0.0 \
  --frame-id world2 \
  --child-frame-id robot_base
```

Now run `view_frames`. There are two separate trees: `world → robot_base → camera_link` and `world2 → robot_base`. TF2 cannot find a path from `world` to `world2` because they are in separate components.

**Diagnosis:** `view_frames` shows two tree components. **Fix:** remove the conflicting publisher (Terminal 3) or connect `world2` as a child of `world` if it is a legitimate frame.

### Failure 4 — Stale transform (simulated)

Kill all three terminals. Restart only Terminal 1 (world → robot_base). Then run:

```bash
ros2 run tf2_ros tf2_echo world robot_base
```

It should work. Now kill Terminal 1 and wait 15 seconds. Try `tf2_echo` again:

```bash
ros2 run tf2_ros tf2_echo world robot_base
```

You will see an extrapolation error: TF2's buffer has the last received transform but it is now "in the past" relative to the query time. Static transforms do not expire this way in practice because `/tf_static` is latched — but dynamic transforms on `/tf` do expire.

**Verification**

- Each failure produces the expected error
- You can identify which diagnostic tool reveals the problem in each case
- You can describe the fix for each failure without referring to notes

## Answer Key

### Exercise 2

**Failure 1:** `view_frames` shows only `world → robot_base` — `camera_link` is absent. The `tf2_echo` error says it cannot find a connection to `camera_link`. Fix: restart the static_transform_publisher for `camera_link`.

**Failure 2:** `rqt_tf_tree` shows `camera_link → robot_base` instead of `robot_base → camera_link`. The tree direction is wrong. `tf2_echo world camera_link` may succeed but return an inverted translation. Fix: restore `--frame-id robot_base --child-frame-id camera_link`.

**Failure 3:** `view_frames` shows two separate tree components: one rooted at `world` and one rooted at `world2`. `tf2_echo world2 camera_link` fails because `camera_link` is not in the `world2` subtree. `tf2_echo world camera_link` works because that path is intact. Fix: kill the `world2` publisher, or add a transform connecting `world → world2`.

**Failure 4:** After the publisher exits, TF2's buffer retains the last transform but marks it as potentially stale. `tf2_echo` will eventually error with "Lookup would require extrapolation into the past" as the query time advances past the buffer's newest entry. Static transforms are technically immune to this because `/tf_static` is latched (subscribers receive the last published value on subscribe), but the exercise approximates the same diagnostic pattern.
