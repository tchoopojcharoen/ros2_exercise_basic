# 4.7 — Visualization with RViz2

## Learning Objectives

By the end of this section, you will be able to:
- Launch RViz2 and configure a basic display
- Explain what the Fixed Frame is and why it must exist in the TF tree
- Add a TF display and an Axes display to visualize coordinate frames
- Save and load an RViz2 configuration file

---

## Before You Begin

This section uses the TF tree from section 4.6. The two `static_transform_publisher` terminals from 4.6 must be running:

- `world → robot_base` (1.0 m forward)
- `robot_base → camera_link` (0.1 m forward, 0.2 m up, -15° pitch)

If you stopped them, restart:

**Terminal 1:**
```bash
ros2 run tf2_ros static_transform_publisher \
  --x 1.0 --y 0.0 --z 0.0 \
  --roll 0.0 --pitch 0.0 --yaw 0.0 \
  --frame-id world \
  --child-frame-id robot_base
```

**Terminal 2:**
```bash
ros2 run tf2_ros static_transform_publisher \
  --x 0.1 --y 0.0 --z 0.2 \
  --roll 0.0 --pitch -0.262 --yaw 0.0 \
  --frame-id robot_base \
  --child-frame-id camera_link
```

Then source and launch RViz2:

```bash
source /opt/ros/humble/setup.bash
rviz2
```

## What RViz2 Is and Is Not

**RViz2 is a viewer.** It subscribes to topics and renders the data visually. It does not simulate physics, send commands, or modify the state of any node.

When something looks wrong in RViz2, the problem is almost always in the data being published — a wrong frame_id, a missing TF transform, or a node that stopped publishing. RViz2 itself is not the source of the problem.

---

## The Fixed Frame

Every display in RViz2 renders relative to one chosen frame called the **Fixed Frame**. All positions and orientations are expressed in this frame.

The Fixed Frame must exist in the TF tree. If it does not exist:
- The status bar at the bottom shows a red warning: "Fixed Frame [X] does not exist"
- Most displays show nothing or red error indicators
- The solution is always in TF, not in RViz2 — either publish the missing frame or change the Fixed Frame to one that exists

To set the Fixed Frame:
1. In the left panel, find **Global Options** at the top
2. Click the value next to **Fixed Frame**
3. Type `world` (or any frame currently in the TF tree)

## Adding Displays

RViz2 displays are added via **Add** at the bottom of the left panel.

### TF Display

The **TF** display shows all frames in the TF tree as colored axis indicators (X=red, Y=green, Z=blue). Each frame appears as a small axes triad at its location relative to the Fixed Frame.

1. Click **Add**
2. Select **TF** from the list
3. Click **OK**
4. In the left panel, expand the **TF** entry. You can control which frames are shown and the scale of the axes.

With `world` as the Fixed Frame and both static publishers running, you should see three triads:
- One at the origin (world frame itself)
- One 1.0 m along X (robot_base)
- One at 1.1 m along X and 0.2 m up (camera_link, slightly tilted by the pitch)

### Axes Display

The **Axes** display shows one specific frame as a larger axis indicator. Useful for highlighting a particular frame.

1. Click **Add**
2. Select **Axes** from the list
3. In the Axes settings, set **Reference Frame** to `camera_link`
4. Adjust **Length** and **Radius** sliders as desired

## Saving and Loading Configurations

RViz2 configurations are saved as `.rviz` files. They record your display list, Fixed Frame, view settings, and panel layout.

### Save

**File → Save Config As...** → navigate to a location, enter a name, click **Save**.

Example: save to `~/tutorial_ws/config/tf_demo.rviz`. You may need to create the `config/` directory first:

```bash
mkdir -p ~/tutorial_ws/config
```

### Load

**File → Open Config** → navigate to the `.rviz` file → click **Open**.

Or, launch RViz2 with a config file directly:

```bash
rviz2 -d ~/tutorial_ws/config/tf_demo.rviz
```

## Exercise 1 — Configure and Save

**Description**

With both static publishers running:

1. Launch `rviz2`.
2. Set Fixed Frame to `world` (Global Options → Fixed Frame).
3. Add a **TF** display. Confirm three frame triads appear.
4. Add an **Axes** display with Reference Frame set to `camera_link`. Set Length to 0.3 m.
5. Create the config directory and save the configuration:
   ```bash
   mkdir -p ~/tutorial_ws/config
   ```
   Then: **File → Save Config As** → `~/tutorial_ws/config/tf_demo.rviz`.
6. Kill both static publishers (`Ctrl+C` in Terminals 1 and 2). Observe the RViz2 status bar — a red warning appears. The displays go red or empty.
7. Restart both static publishers. The warning clears and the triads reappear.

**Verification**

- With both publishers running: three TF triads visible, no red warnings
- After killing publishers: red status warning, displays error
- After restarting publishers: warning clears automatically
- `tf_demo.rviz` file exists in `~/tutorial_ws/config/`

## Exercise 2 — The Fixed Frame Error

**Description**

This exercise demonstrates the most common beginner RViz2 mistake.

1. Close and reopen RViz2 (without loading the config):
   ```bash
   rviz2
   ```

2. Set the Fixed Frame to `robot_arm_link` — a frame that does not exist in your TF tree.

3. Add a TF display.

4. Observe the status bar. You should see:
   ```
   Fixed Frame [robot_arm_link] does not exist
   ```
   And the TF display shows red error indicators for all frames.

5. This is the signature of a TF problem, not an RViz2 problem. The fix is always the same: either publish a transform for the missing frame, or change the Fixed Frame to one that exists.

6. Change the Fixed Frame back to `world`. The error clears.

**Verification**

- Setting a nonexistent Fixed Frame produces a red warning in the status bar
- Changing the Fixed Frame to `world` clears the error without restarting anything

## Answer Key

### Exercise 1

Three frame triads appear because there are three frames in the TF tree (`world`, `robot_base`, `camera_link`). The `camera_link` triad appears slightly tilted because of the -15° pitch transform from `robot_base`.

When publishers are killed, the static transforms remain briefly in TF2's buffer (static transforms are latched), but after a few seconds the buffer may age out. Depending on timing, you may or may not see an immediate red warning. The display going red is TF2 signaling that it no longer has a valid transform.

The `.rviz` file is plain YAML. You can open and edit it by hand to change the Fixed Frame, display list, or view settings without launching RViz2.

### Exercise 2

`robot_arm_link` does not exist because no one has published a transform for it. RViz2 cannot render anything relative to a frame it cannot locate in the TF tree. The red warning is RViz2 reporting a problem in TF, not a problem in RViz2 itself.

The fix is always in TF: either publish the missing frame (add a `static_transform_publisher` for `robot_arm_link`) or choose a Fixed Frame that already exists.

## Troubleshooting

**Nothing appears even with the correct Fixed Frame:**
- Check that the TF displays are checked (enabled checkbox in the left panel)
- Confirm the static publishers are still running: `ros2 topic echo /tf_static`

**RViz2 crashes on remote desktop / SSH:**
- Try: `export LIBGL_ALWAYS_SOFTWARE=1` before launching `rviz2`
- On some systems: `export DISPLAY=:0` if the display variable is not set

**`.rviz` file not found after save:**
- The save dialog shows the full path in the title bar — check where you actually saved it
- `find ~/tutorial_ws -name "*.rviz"` to locate it
