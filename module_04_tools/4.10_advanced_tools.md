## topic_tools

**Package:** `ros-humble-topic-tools` (installed in 4.1)

`topic_tools` provides utility nodes that manipulate topic streams at the transport layer — no custom code needed.

### relay

Republishes messages from one topic to another:

```bash
ros2 run topic_tools relay /turtle1/pose /turtle1/pose_copy
```

`/turtle1/pose_copy` is now a second topic with identical content. Useful for testing without disturbing live subscribers.

### throttle

Rate-limits a topic:

```bash
ros2 run topic_tools throttle messages /turtle1/pose 10.0 /turtle1/pose_slow
```

`/turtle1/pose_slow` receives at most 10 messages per second regardless of how fast the source publishes. The third argument is the output topic (optional; defaults to `<input>_throttle`).

### mux

Selects one of several input topics and republishes it on a single output topic:

```bash
ros2 run topic_tools mux /turtle1/cmd_vel /safe_cmd_vel /teleop_cmd_vel
```

Switch the active input at runtime via the `/mux/select` service. Use case: switch between a safety monitor and a teleop controller without rewiring the system.

## Foxglove Studio

Foxglove Studio is a web-based visualization and debugging interface that replaces `rqt_graph` + `rqt_plot` + `rqt_topic` + RViz2 in a single browser-based tool. It connects to a running ROS2 system via a bridge node.

**Installation:**

```bash
sudo apt install ros-humble-foxglove-bridge
```

Then install the Foxglove Studio desktop app or use the web version at `app.foxglove.dev`.

**Launch the bridge:**

```bash
ros2 launch foxglove_bridge foxglove_bridge_launch.xml
```

Open Foxglove Studio and connect to `ws://localhost:8765`.

**Key panels:**

- 3D: replaces RViz2 for TF, markers, point clouds
- Plot: replaces rqt_plot with higher performance and drag-and-drop fields
- Raw Messages: replaces `ros2 topic echo` with a structured tree view
- Topic Graph: replaces rqt_graph
- Bag Playback: import `.mcap` or `.db3` bags directly (Foxglove natively supports MCAP)

## ros2_tracing

**Package:** `ros-humble-ros2-tracing` + LTTng kernel module

`ros2_tracing` instruments ROS2 callbacks at the kernel level using LTTng (Linux Trace Toolkit, next generation). It records exact callback entry/exit timestamps with nanosecond precision, useful for diagnosing control loop deadline misses.

**Install:**

```bash
sudo apt install ros-humble-ros2-tracing lttng-tools lttng-modules-dkms
```

`lttng-modules-dkms` builds a kernel module — this may take a few minutes and requires a matching kernel header package.

**Quick start:**

```bash
# Enable tracing in your ROS2 node (add to your package):
from tracetools_trace.tools import lttng_tracing

# Or use the CLI:
ros2 trace --session-name my_trace --list-events
ros2 trace --session-name my_trace ros2:callback_start ros2:callback_end
```

Trace files can be analyzed with `babeltrace2` or imported into Eclipse Trace Compass for visualization.

**When to use:** If your control loop misses deadlines intermittently and you cannot identify the cause from log messages, `ros2_tracing` will show you exactly which callback ran at what time and how long it took.

## DDS Traffic Inspection with Wireshark

DDS (the middleware ROS2 uses) communicates over UDP multicast. In a single-machine setup this is all loopback traffic; on a multi-machine system it is broadcast UDP.

**Install Wireshark:**

```bash
sudo apt install wireshark
sudo usermod -aG wireshark $USER
# Log out and back in for group membership to take effect
```

**Filter for DDS traffic:**

In Wireshark, apply the filter:

```
rtps
```

This shows only RTPS (Real-Time Publish-Subscribe) packets — the DDS wire protocol. Port 7400 is DDS discovery (PDP), ports 7401+ are data endpoints.

**When to use:** Cross-host communication is not working and you suspect a network or firewall issue. Wireshark lets you confirm whether DDS discovery packets are leaving and arriving on both machines. `ros2 doctor --report` will show the network interface config but Wireshark shows actual packet flow.

On a single-machine turtlesim setup, all traffic is on the loopback interface and Wireshark adds no insight beyond `ros2 doctor`.

## PlotJuggler (Reminder)

PlotJuggler was introduced as optional in section 4.5. If you found `rqt_plot` limiting during the exercises, PlotJuggler is worth the slightly longer startup time:

```bash
ros2 run plotjuggler_ros plotjuggler
```

Highlights not covered in 4.5:

- **Derived series:** right-click a field → Add Derived Timeseries → apply a math expression (e.g., `$1 * RAD2DEG` to convert radians to degrees)
- **Layout files:** save the entire panel layout to an XML file; load it on next session
- **Bag import:** File → Load Data → select a `.db3` or `.mcap` bag directory; drag fields to a plot pane
- **Publishers panel:** publish to a topic directly from a plot cursor position (advanced use)
