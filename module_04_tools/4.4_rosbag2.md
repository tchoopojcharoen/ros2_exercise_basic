## What is a Bag?

A **bag file** is a recording of ROS2 topic data over time. Each recorded message is stored with its topic name, message type, and a timestamp. You can replay the bag later and the messages are republished on the same topics as if the original nodes were running.

Bags are the primary tool for:
- Capturing a real robot run and analyzing it offline
- Reproducing bugs without running hardware
- Generating datasets for machine learning or analysis
- Sharing data between developers

**What playback does:** republishes the recorded messages on their original topics at the original timestamps (subject to `--rate`).

**What playback does not do:** re-run computation. If you recorded `/turtle1/pose` but not `/turtle1/cmd_vel`, playing the bag back into a fresh turtlesim will not cause the turtle to move — no velocity commands are in the bag. The pose data arrives at the turtlesim node but turtlesim only moves in response to `cmd_vel`.

---

## Storage Formats

rosbag2 supports two storage backends:

| Format | Extension | Default | Notes |
|---|---|---|---|
| SQLite3 | `.db3` | Yes (Humble) | Simple, widely supported, moderate performance |
| MCAP | `.mcap` | No (requires plugin) | Better for large bags, Foxglove-native format |

For most exercises in this section, the default sqlite3 format is fine. MCAP is introduced in the convert exercise.

## Recording

### Record specific topics

```bash
ros2 bag record /turtle1/pose /turtle1/cmd_vel /turtle1/goal
```

This creates a directory named `rosbag2_<date>_<time>/` in the current working directory. The directory contains:

- `<name>.db3` — the bag database
- `metadata.yaml` — topic list, type names, message counts, duration

### Record all topics

```bash
ros2 bag record -a
```

Use `-a` with care on systems with many topics — you may record at very high data rates.

### Specify an output name

```bash
ros2 bag record -o my_run /turtle1/pose /turtle1/cmd_vel
```

The directory will be named `my_run/`. Without `-o`, the name is auto-generated from the timestamp.

### Stop recording

Press `Ctrl+C`. rosbag2 finalizes the database file — wait for the process to exit cleanly before copying or moving the directory.

## Inspecting a Bag

```bash
ros2 bag info <directory>
```

Example output:

```
Files:             rosbag2_2024_01_01-12_00_00/rosbag2_2024_01_01-12_00_00_0.db3
Bag size:          142.8 KiB
Storage id:        sqlite3
Duration:          30.123s
Start:             Jan  1 2024 12:00:00.000 (1704067200.000)
End:               Jan  1 2024 12:00:30.123 (1704067230.123)
Messages:          1874
Topic information:
  Topic: /turtle1/pose | Type: turtlesim/msg/Pose | Count: 1869 | Serialization Format: cdr
  Topic: /turtle1/cmd_vel | Type: geometry_msgs/msg/Twist | Count: 4 | Serialization Format: cdr
  Topic: /turtle1/goal | Type: geometry_msgs/msg/Point | Count: 1
```

The `Count` column tells you how many messages were recorded per topic. A count of 0 for a topic you expected to be active is a diagnostic signal — either the node was not publishing, or there was a QoS mismatch between the recorder and the publisher.

---

## Playing Back

```bash
ros2 bag play <directory>
```

Playback republishes messages at the same rate as they were recorded. Options:

```bash
ros2 bag play <directory> --rate 0.5       # play at half speed
ros2 bag play <directory> --loop           # loop indefinitely
ros2 bag play <directory> --start-offset 5 # skip the first 5 seconds
```

**During playback:** `ros2 topic list` will show the topics from the bag. You can echo them, rqt_plot them, or let nodes subscribe to them as if live data were arriving.

---

## Converting Between Formats

```bash
ros2 bag convert -i <input_dir> -o <output_dir> -s mcap
```

This converts the input bag to MCAP format. The `-s` flag selects the storage plugin. You can also convert mcap back to sqlite3 by swapping the format.

## Exercise 1 — Record, Inspect, and Replay

**Description**

1. Start the full go-to-goal system:

   **Terminal 1:**
   ```bash
   ros2 run turtlesim turtlesim_node
   ```

   **Terminal 2:**
   ```bash
   ros2 run goal_point_publisher goal_point_publisher
   ```

   **Terminal 3:**
   ```bash
   ros2 run turtlesim_controller turtle_controller
   ros2 service call /controller_enabled std_srvs/srv/SetBool "{data: true}"
   ```

2. In **Terminal 4**, start recording:

   ```bash
   ros2 bag record -o navigation_run /turtle1/pose /turtle1/cmd_vel /turtle1/goal
   ```

3. Click **four or five** goal points in the goal publisher window over 30 seconds. Let the turtle reach each goal before clicking the next. Then press `Ctrl+C` in Terminal 4 to stop recording.

4. Inspect the bag:

   ```bash
   ros2 bag info navigation_run
   ```

   Note the message counts for each topic. Is the number of `/turtle1/goal` messages what you expected?

5. Stop all nodes (`Ctrl+C` in Terminals 1-3).

6. Start a fresh turtlesim only:

   ```bash
   ros2 run turtlesim turtlesim_node
   ```

7. Play back the bag:

   ```bash
   ros2 bag play navigation_run
   ```

   Watch the turtlesim window. The turtle should replay its trajectory because `/turtle1/cmd_vel` is in the bag — the commands are republished and turtlesim responds to them. The turtle will not stop at goals because there is no controller running.

**Verification**

- `ros2 bag info` shows three topics with nonzero message counts
- During replay, the turtle moves (because cmd_vel is in the bag)
- The replay ends automatically when the bag runs out of data
- `/turtle1/pose` is visible in `ros2 topic list` during playback (it is being republished)

## Exercise 2 — Pose-Only Bag and Format Conversion

**Description**

1. Start the full system again (as in Exercise 1).

2. Record only `/turtle1/pose` for 20 seconds:

   ```bash
   ros2 bag record -o pose_only /turtle1/pose
   ```

3. Stop recording. Stop all nodes.

4. Start a fresh turtlesim:

   ```bash
   ros2 run turtlesim turtlesim_node
   ```

5. Open `rqt_plot` and add `/turtle1/pose/x` and `/turtle1/pose/y`.

6. Play back the pose-only bag:

   ```bash
   ros2 bag play pose_only
   ```

   Watch `rqt_plot` — the x and y values should trace the turtle's recorded path even though no turtle movement is visible in the turtlesim window (no cmd_vel is in the bag, so the turtle does not actually move in the new session).

7. Convert the bag to MCAP format:

   ```bash
   ros2 bag convert -i pose_only -o pose_only_mcap -s mcap
   ```

   Inspect the new bag:

   ```bash
   ros2 bag info pose_only_mcap
   ```

   Confirm it contains the same topic and message count but shows `Storage id: mcap`.

**Verification**

- During pose-only playback, `rqt_plot` shows the x/y trace but the turtlesim turtle does not move
- `ros2 bag info pose_only_mcap` shows `Storage id: mcap` and the same message count as the original

## Answer Key

### Exercise 1

`/turtle1/goal` count should equal the number of goal points you clicked. The goal publisher sends one message per click. If you clicked five times, you should see `Count: 5` for `/turtle1/goal`.

During replay, the turtle moves because `/turtle1/cmd_vel` is replayed into a live `turtlesim_node` — the simulator does not know the commands came from a bag rather than a live controller. This is exactly what makes rosbag2 useful: the replay is indistinguishable from live data from the subscriber's perspective.

### Exercise 2

Pose-only playback: `rqt_plot` shows the recorded pose trajectory because it subscribes to `/turtle1/pose`, which the bag is republishing. The turtlesim window shows the turtle at its default starting position because no one is sending velocity commands — the turtle is not actually moving in this new session.

MCAP conversion: `ros2 bag convert` requires the `ros-humble-rosbag2-storage-mcap` plugin to be installed. If the command fails with "storage plugin not found", confirm the install from section 4.1.

## Summary

| Command | What it does |
|---|---|
| `ros2 bag record <topics>` | Record to auto-named directory in CWD |
| `ros2 bag record -o <name> <topics>` | Record to named directory |
| `ros2 bag record -a` | Record all active topics |
| `ros2 bag info <dir>` | Show duration, message counts, topic types |
| `ros2 bag play <dir>` | Replay at original rate |
| `ros2 bag play <dir> --rate 0.5` | Replay at half speed |
| `ros2 bag play <dir> --loop` | Loop indefinitely |
| `ros2 bag convert -i <in> -o <out> -s mcap` | Convert to MCAP format |
