## rqt_plot

`rqt_plot` is a simple real-time plotter. It subscribes to any number of numeric topic fields and draws them as time-series lines in a shared plot.

```bash
rqt_plot
```

**Adding a field:**

Type the field expression in the topic input box (top-left) and press **Enter** or click **+**:

```
/turtle1/pose/x
/turtle1/pose/y
/turtle1/pose/theta
```

Each expression is a topic path followed by `.` and a field name. Use `ros2 interface show` to confirm field names before typing — `rqt_plot` will silently show nothing if the path is wrong.

```bash
ros2 interface show turtlesim/msg/Pose
```

Output:
```
float32 x
float32 y
float32 theta
float32 linear_velocity
float32 angular_velocity
```

So the expressions are `/turtle1/pose/x`, `/turtle1/pose/y`, `/turtle1/pose/theta`, `/turtle1/pose/linear_velocity`, `/turtle1/pose/angular_velocity`.

**Removing a field:** Click the field in the list on the left side of the plot, then click the **-** button.

**Y-axis:** Auto-scales continuously. If the turtle moves far, the scale shifts to keep all lines visible.

**Limitations:**
- No persistent configuration — the field list is lost when you close `rqt_plot`
- Struggles with topics above ~100 Hz (the plot becomes noisy and laggy)
- No bag import — use PlotJuggler for offline analysis

## Using rqt_plot for Parameter Tuning

The most productive use of `rqt_plot` is observing the effect of parameter changes in real time.

The go-to-goal controller has (at minimum) a `Kv` gain that scales forward velocity. A higher `Kv` means faster approach but potentially more overshoot; a lower `Kv` means slower, smoother convergence.

While `rqt_plot` is showing `/turtle1/pose/x` and `/turtle1/pose/y`, change `Kv` without restarting the node:

```bash
ros2 param set /turtle_controller Kv 0.5
```

Click a new goal and watch the convergence curve change. Then restore:

```bash
ros2 param set /turtle_controller Kv 2.0
```

This feedback loop — observe → change parameter → observe again — is the core workflow for controller tuning. `rqt_plot` makes the behavior visible in a way that reading log messages cannot.

## PlotJuggler (Optional)

PlotJuggler is a more capable plotting tool for situations where `rqt_plot` falls short:

- High-frequency topics (>200 Hz)
- Bag file analysis (import `.db3` or `.mcap` directly)
- Persistent layout configurations (save/load as XML)
- Derived signals (add, subtract, or transform two fields in the plot)

```bash
ros2 run plotjuggler_ros plotjuggler
```

On first launch, select **ROS2 Topic Subscriber** from the streaming source dropdown, then click **Start**. A topic browser appears — select the topics you want and click **OK**. Drag fields from the left panel into the plot area.

To import a bag: **File → Load Data** → select the `.db3` or `.mcap` directory.

## Exercise 1 — Live Convergence Observation

**Description**

1. Open `rqt_plot`. Add `/turtle1/pose/x` and `/turtle1/pose/y`.

2. Click a goal point in the goal publisher window. Watch the x and y curves converge toward the goal position.

3. While the turtle is navigating, reduce `Kv` by half:
   ```bash
   ros2 param set /turtle_controller Kv 0.5
   ```
   Click a new goal and compare the convergence rate to the previous run. The turtle should reach the goal more slowly.

4. Restore `Kv` to its original value (check your node's default, typically `1.0` or `2.0`):
   ```bash
   ros2 param set /turtle_controller Kv 2.0
   ```

5. Add `/turtle1/pose/linear_velocity` to the plot. Click a goal. Observe the velocity profile — it starts high and decays as the turtle approaches the goal (proportional control: velocity = Kv × distance).

**Verification**

- After reducing `Kv`, the convergence curve is shallower (takes longer to reach the goal)
- `/turtle1/pose/linear_velocity` shows a decaying profile during approach, not a step function
- The plot shows at least three lines simultaneously without freezing

**Description**

## Answer Key

### Exercise 1

The `Kv` parameter scales the commanded forward velocity: `v = Kv × distance`. When `Kv` is halved, the turtle moves at half the speed for the same distance — the convergence curve takes longer to flatten. This is visible as a shallower slope on the x or y trace.

`/turtle1/pose/linear_velocity` shows the actual velocity reported by turtlesim — it tracks the commanded velocity closely at low speeds. The decay toward zero as the turtle approaches the goal is the defining characteristic of proportional control.

### Exercise 2

A goal arrival appears in the velocity trace as a drop to near-zero followed by a flat region (turtle waiting at goal) and then a rising edge as it starts toward the next goal. The number of drops equals the number of goals that were clicked during recording.

During bag playback, `rqt_plot` sees `/turtle1/pose` as a live topic — the bag's republished messages are indistinguishable from live turtlesim output.

## Summary

| Tool | Best for | Not good for |
|---|---|---|
| `rqt_plot` | Live parameter tuning, quick inspection of 2-3 fields | High-frequency topics, bag analysis, saved layouts |
| PlotJuggler | High-frequency data, bag import, saved layouts | Quick one-off checks (heavier startup) |

**Expression syntax:** `/topic_name/field` for top-level fields. Nested fields are not supported directly in `rqt_plot` — use PlotJuggler for nested message access.
