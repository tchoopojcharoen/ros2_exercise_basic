## The Problem: Substitutions Are Not Values

In 5.5, `LaunchConfiguration('radius')` worked inside `parameters` because launch itself evaluates it later. But it is **not** a string. Ordinary Python cannot use it:

```python
radius = LaunchConfiguration('radius')

float(radius)                  # TypeError
radius > 0                     # TypeError
f'circle_{radius}'             # does not contain the argument's value
if radius == 'true': ...       # always False
```

The reason is timing. `generate_launch_description()` runs first and only **builds a description** of what to do. Argument values (`radius:=2.5`) are resolved later, when launch executes that description. When your Python runs, the value does not exist yet.

That rules out anything that needs the value *in Python*: arithmetic, `if` statements, loops, string formatting, validation.

---

## Concept: `OpaqueFunction`

`OpaqueFunction` is a launch action that calls a Python function **at launch time**, after arguments are resolved. It receives the launch `context` and returns a list of actions to run:

```python
from launch.actions import OpaqueFunction

def launch_setup(context, *args, **kwargs):
    radius = LaunchConfiguration('radius').perform(context)   # a real str
    return [ ... actions ... ]

OpaqueFunction(function=launch_setup)
```

- `.perform(context)` is the operation that turns any substitution into a plain `str`. It is only valid where you have a `context`, which is why it lives inside the function
- The returned list can contain any launch actions: `Node`, `LogInfo`, `IncludeLaunchDescription`, and so on. An empty list is allowed
- The function name is arbitrary; `launch_setup` is a common convention
- Convert the string yourself: `float(...)`, `int(...)`, or `... == 'true'` for booleans

The description is "opaque" because launch cannot look inside your function ahead of time. Anything you do in it is invisible to `--show-args`, so **declare arguments outside** the function, in the `LaunchDescription`.

## Step 1 — Read an Argument as a Value

Create `launch/opaque_demo.launch.py`:

```python
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, LogInfo, OpaqueFunction
from launch.substitutions import LaunchConfiguration


def launch_setup(context, *args, **kwargs):
    radius = float(LaunchConfiguration('radius').perform(context))
    return [LogInfo(msg=f'Radius doubled is {radius * 2.0}')]


def generate_launch_description():
    return LaunchDescription([
        DeclareLaunchArgument('radius', default_value='1.0'),
        OpaqueFunction(function=launch_setup),
    ])
```

Build and launch:

```bash
cd ~/tutorial_ws
colcon build --packages-select turtlesim_controller
source ~/tutorial_ws/install/setup.bash
ros2 launch turtlesim_controller opaque_demo.launch.py radius:=1.5
# [INFO] [launch.user]: Radius doubled is 3.0
```

Arithmetic on the argument now works, because `radius` is a real `float`.

A shorter way to read arguments: `context.launch_configurations` is a dict of every argument set so far, with string values (`context.launch_configurations['radius']`). Use `.perform(context)` when the value may come from a substitution such as `PathJoinSubstitution`.

## Step 2 — Validate Arguments

Raise an exception in the function to stop the launch before any node starts:

```python
def launch_setup(context, *args, **kwargs):
    radius = float(LaunchConfiguration('radius').perform(context))
    if radius <= 0.0:
        raise RuntimeError(f'radius must be positive, got {radius}')
    return [LogInfo(msg=f'Radius doubled is {radius * 2.0}')]
```

```bash
ros2 launch turtlesim_controller opaque_demo.launch.py radius:=-1
# [ERROR] [launch]: Caught exception in launch (...): radius must be positive, got -1.0
```

A bad value now produces a clear message at startup, instead of a confusing symptom (a turtle that never moves) several seconds later.

## Step 3 — Build Nodes from an Argument

Because the function returns a list, it can create any number of actions. Add a `count` argument and start that many circle publishers:

```python
from launch_ros.actions import Node


def launch_setup(context, *args, **kwargs):
    radius = float(LaunchConfiguration('radius').perform(context))
    count = int(LaunchConfiguration('count').perform(context))
    if radius <= 0.0:
        raise RuntimeError(f'radius must be positive, got {radius}')
    if count < 1:
        raise RuntimeError(f'count must be at least 1, got {count}')

    return [
        Node(
            package='turtlesim_controller',
            executable='circle_publisher',
            name=f'circle_{i + 1}',
            output='screen',
            parameters=[{'radius': radius * (i + 1)}],
        )
        for i in range(count)
    ]


def generate_launch_description():
    return LaunchDescription([
        DeclareLaunchArgument('radius', default_value='1.0'),
        DeclareLaunchArgument('count', default_value='2'),
        OpaqueFunction(function=launch_setup),
    ])
```

Here the `radius` value is a plain `float`, so it goes into `parameters` with no `ParameterValue` wrapper. Nodes get names built with an f-string, which was impossible with a bare `LaunchConfiguration`.

Rebuild, then launch with turtlesim running in a second terminal:

```bash
ros2 run turtlesim turtlesim_node
```

```bash
ros2 launch turtlesim_controller opaque_demo.launch.py count:=3 radius:=1.0
```

```bash
ros2 node list
# /circle_1
# /circle_2
# /circle_3

ros2 param get /circle_3 radius     # Double value is: 3.0
```

All three publish on `/turtle1/cmd_vel`, so the turtle receives interleaved commands and moves erratically. That is expected; this step shows that the number of nodes is decided at launch time.

## Exercise

**Description**

Extend `opaque_demo.launch.py` with a `mode` argument (default `'circle'`) that takes `'circle'` or `'controller'`.

- `'circle'`: start one `circle_publisher` with the given `radius`
- `'controller'`: start `turtle_lf_controller` as a plain `Node`, with `Kv` set to the value of a `Kv` argument (default `1.0`)
- Any other value raises a `RuntimeError` that names the valid choices

**Requirements**

- `mode:=circle` starts `/circle_publisher`; `mode:=controller Kv:=2.0` starts `/turtle_lf_controller` with `Kv` = `2.0`
- `mode:=banana` stops with an error message listing `circle` and `controller`
- `--show-args` still lists `radius`, `Kv`, and `mode`

## Answer Key

```python
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, OpaqueFunction
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node


def launch_setup(context, *args, **kwargs):
    mode = LaunchConfiguration('mode').perform(context)
    radius = float(LaunchConfiguration('radius').perform(context))
    kv = float(LaunchConfiguration('Kv').perform(context))

    if mode == 'circle':
        return [Node(
            package='turtlesim_controller',
            executable='circle_publisher',
            name='circle_publisher',
            output='screen',
            parameters=[{'radius': radius}],
        )]
    if mode == 'controller':
        return [Node(
            package='turtlesim_controller',
            executable='turtle_lf_controller',
            name='turtle_lf_controller',
            output='screen',
            parameters=[{'Kv': kv}],
        )]
    raise RuntimeError(
        f"mode must be 'circle' or 'controller', got '{mode}'")


def generate_launch_description():
    return LaunchDescription([
        DeclareLaunchArgument('mode', default_value='circle'),
        DeclareLaunchArgument('radius', default_value='1.0'),
        DeclareLaunchArgument('Kv', default_value='1.0'),
        OpaqueFunction(function=launch_setup),
    ])
```

The three `DeclareLaunchArgument` actions stay outside the function so `--show-args` can see them. Everything that depends on the values (the `if` on `mode`, the `float(...)` conversions) lives inside it.

---

## Summary

| Concept | Key point |
|---|---|
| Timing | `generate_launch_description()` builds a description; argument values are resolved later |
| `LaunchConfiguration` | A substitution, not a `str`; use it directly only where launch evaluates it (`parameters`, `arguments`) |
| `OpaqueFunction(function=f)` | Calls `f(context)` at launch time; `f` returns a list of actions |
| `.perform(context)` | Turns a substitution into a plain `str` |
| Use for | Arithmetic, `if`, loops, f-strings, validation on argument values |
| Keep outside | `DeclareLaunchArgument`, so `--show-args` works |
