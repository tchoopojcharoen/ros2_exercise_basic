## Concept: Events and Handlers

Everything that happens during a launch is an **event**: a process starts, prints a line, exits, or launch is asked to shut down. A **handler** is a rule of the form *"when this event happens to that action, do these things"*. You add it to the description with `RegisterEventHandler`:

```python
RegisterEventHandler(
    OnProcessExit(
        target_action=turtlesim_node,    # which action to watch
        on_exit=[LogInfo(msg='turtlesim closed')],   # what to run then
    )
)
```

`OnStateTransition` (used for lifecycle nodes in 5.10) is the same idea for lifecycle events. The common handlers:

| Handler | Fires when | Callback argument |
|---|---|---|
| `OnProcessStart(target_action, on_start)` | The process was spawned | `on_start` |
| `OnProcessExit(target_action, on_exit)` | The process ended | `on_exit` |
| `OnProcessIO(target_action, on_stdout, on_stderr)` | The process wrote a line | `on_stdout`, `on_stderr` |
| `OnShutdown(on_shutdown)` | Launch is shutting down (Ctrl+C or a `Shutdown` event) | `on_shutdown` |

`OnProcessStart`, `OnProcessExit`, and `OnProcessIO` come from `launch.event_handlers`; `Node`, `LifecycleNode`, and `ExecuteProcess` are all valid targets.

The callback can be either:

- a **list of actions** to run (`LogInfo`, `EmitEvent`, `Node`, ...), or
- a **function** `f(event, context)` (or `f(event)`) that returns an action or a list of actions, when you need details of the event

Function callbacks receive the event object. For process events it has `event.process_name` (such as `turtlesim-1`); an exit event also has `event.returncode`; an IO event has `event.text` (`bytes`, so use `.decode()`).

## Concept: Useful Companions

**`TimerAction(period, actions)`** runs actions after a delay. Use it when a process being *started* is not the same as being *ready*:

```python
from launch.actions import TimerAction

TimerAction(period=2.0, actions=[some_node])
```

**`EmitEvent(event=Shutdown(reason=...))`** ends the whole launch, stopping every process, as if you had pressed `Ctrl+C`:

```python
from launch.actions import EmitEvent
from launch.events import Shutdown

EmitEvent(event=Shutdown(reason='turtlesim window closed'))
```

**`LogInfo(msg=...)`** prints a message from launch itself. It is the easiest way to see that a handler fired.

## Step 1 — Log Process Lifecycle Events

Create `launch/events_demo.launch.py`:

```python
from launch import LaunchDescription
from launch.actions import LogInfo, RegisterEventHandler
from launch.event_handlers import OnProcessExit, OnProcessStart
from launch_ros.actions import Node


def generate_launch_description():
    turtlesim_node = Node(
        package='turtlesim',
        executable='turtlesim_node',
        name='turtlesim',
        output='screen',
    )

    on_start = RegisterEventHandler(OnProcessStart(
        target_action=turtlesim_node,
        on_start=[LogInfo(msg='turtlesim process started')],
    ))

    on_exit = RegisterEventHandler(OnProcessExit(
        target_action=turtlesim_node,
        on_exit=[LogInfo(msg='turtlesim process exited')],
    ))

    return LaunchDescription([
        turtlesim_node,
        on_start,
        on_exit,
    ])
```

Build and launch, then close the turtlesim window:

```bash
cd ~/tutorial_ws
colcon build --packages-select turtlesim_controller
source ~/tutorial_ws/install/setup.bash
ros2 launch turtlesim_controller events_demo.launch.py
```

Both messages appear: the first at startup, the second when you close the window. Press `Ctrl+C` if the launch is still running.

## Step 2 — Shut Everything Down When One Node Exits

By default, closing turtlesim leaves the other nodes running. To make turtlesim the "owner" of the system, extend `on_exit` with a shutdown:

```python
from launch.actions import EmitEvent
from launch.events import Shutdown

    on_exit = RegisterEventHandler(OnProcessExit(
        target_action=turtlesim_node,
        on_exit=[
            LogInfo(msg='turtlesim closed, shutting down'),
            EmitEvent(event=Shutdown(reason='turtlesim window closed')),
        ],
    ))
```

Rebuild and launch. Closing the turtlesim window now stops the whole launch, including any other node in the file.

## Step 3 — Run a Node When Another Node Exits

A handler's callback can hold any action, including a `Node`. Use this to react to a failure or a finished job. Here a backup publisher takes over if the main `circle_publisher` exits:

```python
    circle_publisher = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
    )

    circle_backup = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_backup',
        output='screen',
        parameters=[{'radius': 1.0}],
    )

    start_backup = RegisterEventHandler(OnProcessExit(
        target_action=circle_publisher,
        on_exit=[
            LogInfo(msg='circle_publisher exited, starting circle_backup'),
            circle_backup,
        ],
    ))
```

`circle_backup` is **not** in the top-level `LaunchDescription` list: only the handler starts it. Add `circle_publisher` and `start_backup` to the list. Test it from a second terminal:

```bash
pkill -f "__node:=circle_publisher"
ros2 node list
# /circle_backup
# /turtlesim
```

Use a **new** `Node` action with a new name for the replacement; the same action object is not run twice.

## Concept: When Is a Node "Loaded"?

`OnProcessStart` fires the moment the process is spawned, long before a node has finished initialising. To start a node after another one is really **ready**, use a signal the first node produces:

| Signal | Handler | Use when |
|---|---|---|
| A lifecycle state was reached | `OnStateTransition(goal_state=...)` | The node is a lifecycle node (5.10) |
| The node printed a readiness message | `OnProcessIO(on_stdout / on_stderr)` | The node logs something when it is up |
| Neither is available | `TimerAction(period=...)` | Last resort: a fixed delay is a guess |

## Step 4 — Run a Node When Another Prints "Ready"

When turtlesim finishes starting it logs `Spawning turtle [turtle1] at ...`. That is a good signal that it is ready to receive commands. Start `circle_publisher` when this line appears:

```python
from launch.event_handlers import OnProcessIO

    circle_publisher = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
    )

    def on_turtlesim_output(event):
        if 'Spawning turtle' in event.text.decode():
            return [
                LogInfo(msg='turtlesim is ready, starting circle_publisher'),
                circle_publisher,
            ]

    start_when_ready = RegisterEventHandler(OnProcessIO(
        target_action=turtlesim_node,
        on_stderr=on_turtlesim_output,
    ))
```

Put `turtlesim_node` and `start_when_ready` in the `LaunchDescription` list; `circle_publisher` is started by the handler. Launch it: the turtlesim window opens, the log line appears, and only then does the turtle start drawing circles.

Notes:

- ROS 2 loggers write to **stderr**, so use `on_stderr`. If a message does not appear, try `on_stdout`
- The function is called for every chunk of output. Return `None` (or nothing, as here) when the text does not match
- The event text is `bytes`, so call `.decode()`
- A message that could appear more than once would start the node more than once. Guard it with a flag, or use a message printed only once

**The same idea with a delay.** If the node prints nothing useful, fall back on `TimerAction`:

```python
from launch.actions import TimerAction

    start_circle_later = RegisterEventHandler(OnProcessStart(
        target_action=turtlesim_node,
        on_start=[TimerAction(period=2.0, actions=[circle_publisher])],
    ))
```

A fixed delay is a guess, like the `sleep` calls in Module 4's script.

## Step 5 — Combine: Start, Run, and Shut Down

The full pattern for a small supervised system:

```python
    return LaunchDescription([
        turtlesim_node,
        start_when_ready,        # start circle_publisher when turtlesim is ready
        start_backup,            # ... and a backup if it exits
        on_exit,                 # shut down everything when turtlesim closes (Step 2)
    ])
```

Each handler is a separate rule. Rules that watch different targets do not interfere with each other.

**Making a handler optional.** `RegisterEventHandler` accepts a `condition` like any other action (5.8). For example, register the shutdown rule only when a launch argument asks for it:

```python
    on_exit = RegisterEventHandler(
        OnProcessExit(
            target_action=turtlesim_node,
            on_exit=[EmitEvent(event=Shutdown(reason='turtlesim closed'))],
        ),
        condition=IfCondition(LaunchConfiguration('exit_with_sim')),
    )
```

When the condition is false, the handler is never registered.

## Answer Key

```python
from launch import LaunchDescription
from launch.actions import EmitEvent, LogInfo, RegisterEventHandler
from launch.event_handlers import OnProcessExit, OnProcessIO, OnShutdown
from launch.events import Shutdown
from launch_ros.actions import Node


def on_circle_exit(event, context):
    return [
        LogInfo(msg=f'{event.process_name} exited with code '
                    f'{event.returncode}'),
        Node(
            package='turtlesim_controller',
            executable='circle_publisher',
            name='circle_backup',
            output='screen',
            parameters=[{'radius': 1.0}],
        ),
    ]


def generate_launch_description():
    turtlesim_node = Node(
        package='turtlesim',
        executable='turtlesim_node',
        name='turtlesim',
        output='screen',
    )

    circle_publisher = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
    )

    def on_turtlesim_output(event):
        if 'Spawning turtle' in event.text.decode():
            return [circle_publisher]

    start_when_ready = RegisterEventHandler(OnProcessIO(
        target_action=turtlesim_node,
        on_stderr=on_turtlesim_output,
    ))

    backup_on_exit = RegisterEventHandler(OnProcessExit(
        target_action=circle_publisher,
        on_exit=on_circle_exit,
    ))

    shutdown_with_turtlesim = RegisterEventHandler(OnProcessExit(
        target_action=turtlesim_node,
        on_exit=[EmitEvent(event=Shutdown(reason='turtlesim closed'))],
    ))

    log_finished = RegisterEventHandler(OnShutdown(
        on_shutdown=[LogInfo(msg='Supervised launch finished')],
    ))

    return LaunchDescription([
        turtlesim_node,
        start_when_ready,
        backup_on_exit,
        shutdown_with_turtlesim,
        log_finished,
    ])
```

Each requirement is its own small rule, matching the *event* (exit, shutdown) on a *target* to a list of *reactions*. The two `OnProcessExit` handlers watch different targets, so only turtlesim's exit triggers `Shutdown`. `on_exit=on_circle_exit` passes a function, which is needed here because the message uses details of the event.

## Summary

| Concept | Key point |
|---|---|
| Event handler | "When event X happens to target Y, run these actions" |
| `RegisterEventHandler(...)` | Adds a handler to the launch description |
| `OnProcessStart`, `OnProcessExit`, `OnProcessIO`, `OnShutdown` | The general-purpose handlers; `OnStateTransition` is the lifecycle one |
| Callback | A list of actions, or a function `f(event, context)` returning actions |
| Run a node on an event | Put the `Node` in the handler's callback list, not in the top-level list |
| "Loaded" signals | `OnStateTransition` (lifecycle), `OnProcessIO` (a log line), `TimerAction` (last resort) |
| `TimerAction(period, actions)` | Run actions after a delay |
| `EmitEvent(Shutdown(reason=...))` | Stop the whole launch |
| Started is not ready | `OnProcessStart` fires when the process spawns; delay or wait for a real signal |
