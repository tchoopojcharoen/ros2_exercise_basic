## Why Conditions?

One launch file often has to serve several situations: with or without the goal GUI, in simulation or on hardware, with or without logging. Writing a launch file per case duplicates code. A **condition** lets one file decide, at launch time, which parts to run:

```bash
ros2 launch turtlesim_controller conditional.launch.py gui:=false
```

---

## Concept: `condition=`

Almost every launch action accepts a `condition` argument, including `Node`, `LifecycleNode`, `IncludeLaunchDescription`, `ExecuteProcess`, `LogInfo`, `GroupAction`, `RegisterEventHandler`, and `EmitEvent`. If the condition is false at launch time, the action is skipped:

```python
from launch.conditions import IfCondition, UnlessCondition
from launch.substitutions import LaunchConfiguration

Node(
    package='goal_point_publisher',
    executable='goal_point_publisher',
    condition=IfCondition(LaunchConfiguration('gui')),
)
```

| Condition | The action runs when |
|---|---|
| `IfCondition(expr)` | `expr` evaluates to true |
| `UnlessCondition(expr)` | `expr` evaluates to false |

The expression is usually a `LaunchConfiguration`, so the condition is evaluated **after** the arguments are known. This is the key difference from a plain Python `if`, which would run while the description is being built and cannot see argument values (5.7).

**Accepted values.** A string expression must be `true`, `false`, `1`, or `0` (case-insensitive). Anything else, such as `yes`, stops the launch with `invalid condition expression`. Declare boolean arguments with a default of `'true'` or `'false'`.

---

## Concept: Comparisons with `PythonExpression`

An argument like `mode:=circle` is not a boolean. Turn a comparison into one with `PythonExpression`, which evaluates a Python expression at launch time. It takes a list of strings and substitutions that are joined into the expression:

```python
from launch.substitutions import PythonExpression

is_circle = IfCondition(
    PythonExpression(["'", LaunchConfiguration('mode'), "' == 'circle'"])
)
```

With `mode:=circle`, the expression becomes `'circle' == 'circle'` and evaluates to `True`.

**Quote the value.** The substitution inserts raw text. Without the surrounding quotes, the expression would be `circle == 'circle'`, and Python would fail with `name 'circle' is not defined`. This is also why `PythonExpression([LaunchConfiguration('gui'), " == True"])` fails for `gui:=false`: `false` is not a Python name. Compare quoted strings, or use `IfCondition(LaunchConfiguration(...))` directly for booleans.

## Step 1 — Optional Goal GUI

Create `launch/conditional.launch.py` with turtlesim always on and the goal GUI optional:

```python
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, LogInfo
from launch.conditions import IfCondition, UnlessCondition
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node


def generate_launch_description():
    gui_arg = DeclareLaunchArgument(
        'gui',
        default_value='true',
        description='Start the goal_point_publisher GUI',
    )

    turtlesim_node = Node(
        package='turtlesim',
        executable='turtlesim_node',
        name='turtlesim',
        output='screen',
    )

    goal_gui = Node(
        package='goal_point_publisher',
        executable='goal_point_publisher',
        name='goal_point_publisher',
        output='screen',
        condition=IfCondition(LaunchConfiguration('gui')),
    )

    no_gui_note = LogInfo(
        msg='Goal GUI disabled: publish goals with ros2 topic pub /goal',
        condition=UnlessCondition(LaunchConfiguration('gui')),
    )

    return LaunchDescription([
        gui_arg,
        turtlesim_node,
        goal_gui,
        no_gui_note,
    ])
```

Build and launch both ways:

```bash
cd ~/tutorial_ws
colcon build --packages-select turtlesim_controller
source ~/tutorial_ws/install/setup.bash
ros2 launch turtlesim_controller conditional.launch.py
ros2 launch turtlesim_controller conditional.launch.py gui:=false
```

With the default, the GUI opens. With `gui:=false`, only turtlesim starts and the note is printed; `ros2 node list` does not show `/goal_point_publisher`. Stop each launch with `Ctrl+C`.

## Step 2 — Choose Between Alternatives

Two mutually exclusive nodes, selected by a `mode` argument, using `PythonExpression`:

```python
    mode_arg = DeclareLaunchArgument('mode', default_value='circle')

    circle_publisher = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
        condition=IfCondition(PythonExpression(
            ["'", LaunchConfiguration('mode'), "' == 'circle'"])),
    )

    controller = Node(
        package='turtlesim_controller',
        executable='turtle_lf_controller',
        name='turtle_lf_controller',
        output='screen',
        condition=IfCondition(PythonExpression(
            ["'", LaunchConfiguration('mode'), "' == 'controller'"])),
    )
```

Add `mode_arg`, `circle_publisher`, and `controller` to the `LaunchDescription` list. Then:

```bash
ros2 launch turtlesim_controller conditional.launch.py mode:=controller
ros2 node list
# /turtle_lf_controller
# /turtlesim
# /goal_point_publisher
```

Both nodes are always *declared*; the conditions decide which one runs. A misspelt mode such as `mode:=banana` silently runs neither. That is a good reason to use `OpaqueFunction` when you need validation (5.7).

## Step 3 — Conditions on Groups, Includes, and Handlers

A `GroupAction` applies one condition to several actions:

```python
from launch.actions import GroupAction

    simulation = GroupAction(
        condition=IfCondition(LaunchConfiguration('sim')),
        actions=[
            turtlesim_node,
            goal_gui,
        ],
    )
```

Conditions also work on includes:

```python
    sim = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(sim_launch_path),
        condition=IfCondition(LaunchConfiguration('sim')),
    )
```

A condition on a `GroupAction` covers everything inside it, so a node in a group does not need its own. Conditions on event handlers (`RegisterEventHandler`) are covered in 5.9.

---

## Concept: Conditions or `OpaqueFunction`?

| Need | Use |
|---|---|
| Turn an action on or off from a boolean argument | `IfCondition` / `UnlessCondition` |
| Pick one of a few alternatives by comparing a string | `IfCondition(PythonExpression(...))` |
| Validate values, do arithmetic, or build a variable number of nodes | `OpaqueFunction` (5.7) |
| Complex logic with several interacting arguments | `OpaqueFunction`, where you can use normal Python `if` |

Conditions keep the launch file declarative and visible to launch; `OpaqueFunction` gives you full Python at the price of hiding the logic inside a function.

## Exercise

**Description**

Extend `conditional.launch.py` with an optional recording. Add a boolean argument `record` (default `'false'`) and an `ExecuteProcess` that runs `ros2 bag record /turtle1/pose /turtle1/cmd_vel` (Module 4.4) only when `record` is true. Add a second `LogInfo` that prints `Recording disabled` when it is false.

**Requirements**

- `record:=true`: a `rosbag2_...` directory is created in the current directory and `ros2 bag info` lists both topics
- Default launch: no bag process starts, and `Recording disabled` is logged
- `--show-args` lists `gui`, `mode`, and `record`

---

## Answer Key

```python
from launch.actions import DeclareLaunchArgument, ExecuteProcess, LogInfo

    record_arg = DeclareLaunchArgument(
        'record',
        default_value='false',
        description='Record /turtle1/pose and /turtle1/cmd_vel to a bag',
    )

    bag_record = ExecuteProcess(
        cmd=['ros2', 'bag', 'record', '/turtle1/pose', '/turtle1/cmd_vel'],
        output='screen',
        condition=IfCondition(LaunchConfiguration('record')),
    )

    no_record_note = LogInfo(
        msg='Recording disabled',
        condition=UnlessCondition(LaunchConfiguration('record')),
    )
```

Add `record_arg`, `bag_record`, and `no_record_note` to the `LaunchDescription` list. `ExecuteProcess` runs any command, not only ROS nodes, and it accepts a `condition` like every other action. Pressing `Ctrl+C` stops the bag recording cleanly along with the rest of the launch.

A condition on an event handler is introduced in 5.9, and the 5.11 stretch exercises use one to make lifecycle activation optional.

## Summary

| Concept | Key point |
|---|---|
| `condition=` | Accepted by almost every action; a false condition skips it |
| `IfCondition(expr)` / `UnlessCondition(expr)` | Run when `expr` is true / false |
| Valid values | `true`, `false`, `1`, `0` (case-insensitive); anything else stops the launch |
| `PythonExpression([...])` | Compare or compute at launch time; quote string values |
| `GroupAction(condition=..., actions=[...])` | One condition for several actions |
| Conditions vs `OpaqueFunction` | Conditions for on/off and simple choices; `OpaqueFunction` for validation and loops |
