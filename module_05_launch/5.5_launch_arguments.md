## Why Arguments?

So far, changing the circle radius meant editing a file and rebuilding. A **launch argument** is a parameter of the launch file itself: the user sets it when launching, and the launch file passes it on:

```bash
ros2 launch turtlesim_controller circle_args.launch.py radius:=2.5
```

Do not confuse the two layers:

| | ROS parameter | Launch argument |
|---|---|---|
| Belongs to | A running node | The launch file |
| Set with | `ros2 param set`, YAML, `parameters=` | `name:=value` after the launch file |
| Lifetime | While the node runs | Read once at launch |

A launch argument is only useful once you connect it to something, most often a node parameter.

---

## Concept: Declare, Read, Use

Three pieces:

```python
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration

radius_arg = DeclareLaunchArgument(
    'radius',
    default_value='1.0',
    description='Circle radius in turtlesim units',
)

radius = LaunchConfiguration('radius')
```

- `DeclareLaunchArgument` is an **action**: it must be included in the `LaunchDescription` list
- `default_value` is a **string**, even for numbers
- `LaunchConfiguration('radius')` is a **substitution**: it is replaced with the argument's value when the launch runs, not when the Python function runs

Because the value arrives as a string, tell ROS what type the parameter should be with `ParameterValue`:

```python
from launch_ros.parameter_descriptions import ParameterValue

parameters=[{'radius': ParameterValue(radius, value_type=float)}]
```

Without `ParameterValue`, the string `'2.5'` may be sent as a string parameter, and a node that declared `radius` as a double will reject it.

## Step 1 — Write the Launch File

Create `~/tutorial_ws/src/turtlesim_controller/launch/circle_args.launch.py`:

```python
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    radius_arg = DeclareLaunchArgument(
        'radius',
        default_value='1.0',
        description='Circle radius in turtlesim units',
    )
    speed_arg = DeclareLaunchArgument(
        'angular_speed',
        default_value='1.0',
        description='Angular speed in rad/s',
    )

    turtlesim_node = Node(
        package='turtlesim',
        executable='turtlesim_node',
        name='turtlesim',
        output='screen',
    )

    circle_publisher = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
        parameters=[{
            'radius': ParameterValue(
                LaunchConfiguration('radius'), value_type=float),
            'angular_speed': ParameterValue(
                LaunchConfiguration('angular_speed'), value_type=float),
        }],
    )

    return LaunchDescription([
        radius_arg,
        speed_arg,
        turtlesim_node,
        circle_publisher,
    ])
```

## Step 3 — Launch with Defaults and Overrides

```bash
ros2 launch turtlesim_controller circle_args.launch.py
```

The turtle draws a small circle. In a second terminal:

```bash
ros2 param get /circle_publisher radius   # Double value is: 1.0
```

Stop the launch, then override one argument:

```bash
ros2 launch turtlesim_controller circle_args.launch.py radius:=2.5
```

```bash
ros2 param get /circle_publisher radius          # Double value is: 2.5
ros2 param get /circle_publisher angular_speed   # Double value is: 1.0
```

Several arguments combine on one line:

```bash
ros2 launch turtlesim_controller circle_args.launch.py radius:=2.5 angular_speed:=0.8
```

An unknown name, such as `radus:=2.5`, is not an error: launch ignores it and the default is used. When a value has no effect, check the spelling with `--show-args`.

## Exercise

**Description**

Add a third argument `use_sim_time` (default `'false'`) to `circle_args.launch.py`. Pass it to `circle_publisher` as the parameter `use_sim_time`, typed as a boolean.

**Requirements**

- `--show-args` lists all three arguments
- `ros2 param get /circle_publisher use_sim_time` returns `Boolean value is: False` by default
- With `use_sim_time:=true`, it returns `Boolean value is: True`

---

## Answer Key

Add the declaration:

```python
    sim_time_arg = DeclareLaunchArgument(
        'use_sim_time',
        default_value='false',
        description='Use simulated clock',
    )
```

Add the parameter to the `circle_publisher` dict:

```python
            'use_sim_time': ParameterValue(
                LaunchConfiguration('use_sim_time'), value_type=bool),
```

Add `sim_time_arg` to the `LaunchDescription` list. `use_sim_time` is a parameter that every ROS 2 node declares automatically, so `circle_publisher` needs no code change. `value_type=bool` turns the string `'true'` into a real boolean.

---

## Summary

| Concept | Key point |
|---|---|
| `DeclareLaunchArgument(name, default_value=...)` | Declares an argument; defaults are strings; must be in the `LaunchDescription` |
| `LaunchConfiguration(name)` | Substitution that is replaced by the argument's value at launch |
| `ParameterValue(sub, value_type=...)` | Converts the string to `float`, `int`, `bool`, or `str` |
| `name:=value` | Command-line override |
| `--show-args` | Lists a launch file's arguments and defaults |
