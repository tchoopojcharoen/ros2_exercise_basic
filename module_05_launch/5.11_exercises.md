## Exercise — The Final Launch File

**Description**

Write `launch/go_to_goal.launch.py`. It starts the complete system of the README's final diagram with one command:

```bash
ros2 launch turtlesim_controller go_to_goal.launch.py
```

```
goal_point_publisher ──► /goal ──► turtle_lf_controller ──► /turtle1/cmd_vel ──► turtlesim
                                        ▲                                            │
                                        └──────────────── /turtle1/pose ◄────────────┘
```

**Requirements**

1. **Include** `sim.launch.py` to start turtlesim and the goal GUI
2. **YAML**: `tolerance` comes from a new file `config/go_to_goal.yaml`, loaded through `ParameterFile` with `FindPackageShare`
3. **Arguments**: declare `Kv` (default `1.0`), `Kw` (default `5.0`), and `frequency` (default `10.0`). `Kv` and `Kw` override the controller's parameters after the YAML; `frequency` is forwarded as the `--frequency` command-line argument
4. **Lifecycle**: the controller is a `LifecycleNode` that configures and then activates itself when launch starts, with the handler registered before the first transition
5. Add the file to `setup.py` if needed (the existing `launch/` and `config/` globs already cover it) and rebuild

**Checks**

```bash
ros2 launch turtlesim_controller go_to_goal.launch.py --show-args
# lists Kv, Kw, frequency (and background_b if you forwarded it)

ros2 launch turtlesim_controller go_to_goal.launch.py Kv:=2.0 frequency:=20.0
```

In a second terminal:

```bash
ros2 lifecycle get /turtle_lf_controller    # active [3]
ros2 param get /turtle_lf_controller Kv     # Double value is: 2.0
ros2 param get /turtle_lf_controller tolerance   # Double value is: 0.05
ros2 topic hz /turtle1/cmd_vel              # about 20 Hz while moving
```

Click in the goal GUI: the turtle drives to the point and stops within the tolerance.

Try to write it yourself first, using 5.4 to 5.10 as reference.

## Answer Key

`config/go_to_goal.yaml`:

```yaml
turtle_lf_controller:
  ros__parameters:
    tolerance: 0.05
```

`launch/go_to_goal.launch.py`:

```python
from launch import LaunchDescription
from launch.actions import (
    DeclareLaunchArgument, EmitEvent, IncludeLaunchDescription,
    RegisterEventHandler)
from launch.events import matches_action
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration, PathJoinSubstitution
from launch_ros.actions import LifecycleNode
from launch_ros.event_handlers import OnStateTransition
from launch_ros.events.lifecycle import ChangeState
from launch_ros.parameter_descriptions import ParameterFile, ParameterValue
from launch_ros.substitutions import FindPackageShare
from lifecycle_msgs.msg import Transition


def generate_launch_description():
    kv_arg = DeclareLaunchArgument('Kv', default_value='1.0')
    kw_arg = DeclareLaunchArgument('Kw', default_value='5.0')
    frequency_arg = DeclareLaunchArgument('frequency', default_value='10.0')

    sim = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            PathJoinSubstitution([
                FindPackageShare('turtlesim_controller'),
                'launch',
                'sim.launch.py',
            ])
        ),
    )

    config = ParameterFile(
        PathJoinSubstitution([
            FindPackageShare('turtlesim_controller'),
            'config',
            'go_to_goal.yaml',
        ]),
        allow_substs=True,
    )

    controller = LifecycleNode(
        package='turtlesim_controller',
        executable='turtle_lf_controller',
        name='turtle_lf_controller',
        namespace='',
        output='screen',
        parameters=[
            config,
            {
                'Kv': ParameterValue(
                    LaunchConfiguration('Kv'), value_type=float),
                'Kw': ParameterValue(
                    LaunchConfiguration('Kw'), value_type=float),
            },
        ],
        arguments=['--frequency', LaunchConfiguration('frequency')],
    )

    activate_after_configure = RegisterEventHandler(OnStateTransition(
        target_lifecycle_node=controller,
        goal_state='inactive',
        entities=[EmitEvent(event=ChangeState(
            lifecycle_node_matcher=matches_action(controller),
            transition_id=Transition.TRANSITION_ACTIVATE,
        ))],
    ))

    configure = EmitEvent(event=ChangeState(
        lifecycle_node_matcher=matches_action(controller),
        transition_id=Transition.TRANSITION_CONFIGURE,
    ))

    return LaunchDescription([
        kv_arg,
        kw_arg,
        frequency_arg,
        sim,
        controller,
        activate_after_configure,
        configure,
    ])
```

How the pieces fit:

- **Include** brings in turtlesim and the goal GUI (5.6)
- **`parameters=[config, {...}]`** layers the YAML first and the argument values on top (5.4); a value passed at launch always wins over the file
- **`ParameterValue`** converts the string arguments to floats (5.5)
- **`arguments=[..., LaunchConfiguration(...)]`** accepts a substitution, so `frequency:=20.0` reaches the controller's argparse
- **Event handler before `configure`** guarantees the controller activates (5.10)

## Stretch Exercises

1. **Namespace the whole system.** Wrap the nodes in a `GroupAction` with `PushRosNamespace('robot')`. What breaks, and which remappings (5.2) fix it?
2. **Configure only.** Add a launch argument `autostart` (default `'true'`). Put an `IfCondition` on the `RegisterEventHandler` that activates the controller, so `autostart:=false` leaves it `inactive` until you activate it by hand (5.8, 5.10)
3. **Supervise the system.** Shut everything down when the controller process exits, and log its return code first (5.9)
4. **Record the run.** Add an `ExecuteProcess` action that starts `ros2 bag record /turtle1/pose /turtle1/cmd_vel /goal` (Module 4.4), controlled by a `record` argument and an `IfCondition` (5.8)

## Summary

| Module 5 tool | Used for |
|---|---|
| `Node` / `LifecycleNode` | Declaring nodes; lifecycle nodes for transitions |
| `namespace`, `remappings` | Naming and wiring (5.2) |
| YAML + `ParameterFile` | Parameter values kept out of code (5.3, 5.4) |
| `DeclareLaunchArgument` + `LaunchConfiguration` | Values chosen at launch time (5.5) |
| `IncludeLaunchDescription` | Composing launch files (5.6) |
| `OpaqueFunction` | Using argument values as Python values (5.7) |
| `IfCondition` / `UnlessCondition` | Turning parts of the system on or off (5.8) |
| Event handlers | Reacting to nodes starting, exiting, or printing (5.9) |
| `EmitEvent` + `OnStateTransition` | Automating lifecycle startup (5.10) |
