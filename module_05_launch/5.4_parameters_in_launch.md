## Concept: Layering Parameter Sources

The `parameters` list can mix files and dicts, and they are applied **in order**. Later entries override earlier ones for the same parameter:

```python
parameters=[
    config,                      # 1. defaults from the YAML file
    {'radius': 4.0},             # 2. overrides radius only
]
```

The resulting value for `radius` is `4.0`; everything else still comes from the file. The full ordering, lowest to highest priority:

| Priority | Source |
|---|---|
| Lowest | `declare_parameter(name, default)` in the node |
| ↓ | Entries in the `parameters` list, first to last |
| Highest | `ros2 param set` at runtime |

The last row is temporary: a runtime `ros2 param set` lives only as long as the process. Relaunch, and the node starts again from the launch file. To make a change permanent, edit the YAML and rebuild.

## Concept: Substitutions for Paths

`get_package_share_directory` runs in Python while the launch description is *built*. Launch also offers **substitutions**, small objects that are evaluated when the action *runs*. They are the standard way to build paths:

```python
from launch_ros.substitutions import FindPackageShare
from launch.substitutions import PathJoinSubstitution

config = PathJoinSubstitution([
    FindPackageShare('turtlesim_controller'),
    'config',
    'circles.yaml',
])
```

- `FindPackageShare('pkg')` resolves to the package's `share/` directory
- `PathJoinSubstitution([...])` joins the parts with the right separator

A substitution cannot go directly into `parameters` as a bare path. Wrap it in `ParameterFile`:

```python
from launch_ros.parameter_descriptions import ParameterFile

parameters=[ParameterFile(config, allow_substs=True)]
```

For a plain string path (as in 5.3) you do not need `ParameterFile`. You need it when the path is a substitution. Substitutions matter from 5.5 onward, where values are decided when the user launches.

## Concept: Arguments vs Parameters

Not everything is a parameter. `turtle_lf_controller` reads `--frequency` from the command line (Module 3.2). In a launch file, pass such arguments with `arguments`:

```python
Node(
    package='turtlesim_controller',
    executable='turtle_lf_controller',
    name='turtle_lf_controller',
    arguments=['--frequency', '20.0'],
)
```

Launch appends its own `--ros-args ...` after yours. The controller's `parse_known_args()` splits the two, which is the reason Module 3 used it.

## Step 1 — Layer an Override

Edit `turtlesim.launch.py`. Add an inline dict after the file for the first publisher:

```python
    circle_turtle1 = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
        parameters=[config, {'radius': 4.0}],
    )
```

Rebuild if you edited the YAML; a launch-file edit needs `colcon build` too, since it is installed. Launch and check:

```bash
ros2 param get /circle_publisher radius         # Double value is: 4.0
ros2 param get /circle_publisher angular_speed  # Double value is: 2.0 (from the file)
```

Swap the order (`[{'radius': 4.0}, config]`) and rebuild: `radius` returns `3.0`, because the file now comes last.

## Step 2 — Use Substitutions

Replace the `os.path` code with substitutions:

```python
from launch import LaunchDescription
from launch.substitutions import PathJoinSubstitution
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterFile
from launch_ros.substitutions import FindPackageShare


def generate_launch_description():
    config = ParameterFile(
        PathJoinSubstitution([
            FindPackageShare('turtlesim_controller'),
            'config',
            'circles.yaml',
        ]),
        allow_substs=True,
    )
    ...
```

The rest of the file is unchanged, and `parameters=[config, {...}]` works as before. Rebuild, relaunch, and confirm the same parameter values.

## Step 3 — Check What the Node Really Got

Dump the live parameters of one node:

```bash
ros2 param dump /circle_publisher
```

This prints the YAML the node is using now, after layering. It is the ground truth when you are unsure which source won.

## Exercise

**Description**

Add `turtle_lf_controller` to `turtlesim.launch.py` as a plain `Node`. Give it:

- Parameters from a new file `config/controller.yaml` with `Kv: 1.5`, `Kw: 4.0`, `tolerance: 0.05`
- An inline override `tolerance: 0.02` on top of the file
- The command-line argument `--frequency 20.0`

**Requirements**

- `ros2 param get /turtle_lf_controller Kv` returns `1.5`
- `ros2 param get /turtle_lf_controller tolerance` returns `0.02`
- After `configure` and `activate`, and one goal published with `ros2 topic pub --once /goal geometry_msgs/msg/Point "{x: 9.0, y: 9.0}"`, `ros2 topic hz /turtle1/cmd_vel` reports about `20 Hz` while the turtle moves

The controller is a lifecycle node, so it stays `unconfigured` until you configure it by hand. Automating that is the subject of 5.10.

---

## Answer Key

`config/controller.yaml`:

```yaml
turtle_lf_controller:
  ros__parameters:
    Kv: 1.5
    Kw: 4.0
    tolerance: 0.05
```

Added to `turtlesim.launch.py`:

```python
    controller_params = ParameterFile(
        PathJoinSubstitution([
            FindPackageShare('turtlesim_controller'),
            'config',
            'controller.yaml',
        ]),
        allow_substs=True,
    )

    controller = Node(
        package='turtlesim_controller',
        executable='turtle_lf_controller',
        name='turtle_lf_controller',
        output='screen',
        parameters=[controller_params, {'tolerance': 0.02}],
        arguments=['--frequency', '20.0'],
    )
```

Add `controller` to the `LaunchDescription` list. Rebuild so `controller.yaml` is installed.

`Node` is enough for a lifecycle node here because its parameters are declared in `__init__`, so they are applied at startup, before any lifecycle transition. Only the *transitions* need `LifecycleNode` (5.10).

## Summary

| Concept | Key point |
|---|---|
| Layering | `parameters=[...]` is applied in order; later wins |
| Runtime changes | `ros2 param set` overrides everything but is lost on relaunch |
| Substitutions | `FindPackageShare` + `PathJoinSubstitution` build paths at launch time |
| `ParameterFile` | Wrap a substitution path so it is loaded as YAML |
| `arguments` | Passes plain command-line args (not `--ros-args`) to the executable |
| Inspecting | `ros2 param dump /node` shows the values in effect |
