## Why YAML?

Inline dicts work for two parameters. With ten parameters across several nodes, the launch file turns into a wall of numbers, and changing a value means editing code. A **parameter file** keeps the values in one place, separate from the launch logic. You met the format in Module 1 with `ros2 param dump`; now launch loads it for you.

---

## Concept: The YAML Structure

```yaml
circle_publisher:
  ros__parameters:
    radius: 3.0
    angular_speed: 1.5

/turtle2/circle_publisher:
  ros__parameters:
    radius: 1.0
    angular_speed: 3.0
```

- The top-level key is the **node name** the values apply to. A plain name matches a node with no namespace; use the full path (`/turtle2/circle_publisher`) for a namespaced node
- `ros__parameters` (two underscores) is required; anything else under the node key is ignored
- Keys under `ros__parameters` are parameter names, with YAML types (`3.0` is a double, `3` is an integer)
- **Types must match the node's declaration.** `radius: 3` on a parameter declared as `1.0` is rejected because an integer is not a double

**Wildcards.** The key `/**` matches every node, in every namespace:

```yaml
/**:
  ros__parameters:
    radius: 2.0
```

A specific entry overrides a wildcard entry for the same parameter, so wildcards are handy for shared defaults.

## Step 2 — Install `config/` in `setup.py`

Like launch files, config files must be installed to the package share directory. Add one line to `data_files`:

```python
    data_files=[
        ('share/ament_index/resource_index/packages',
            ['resource/' + package_name]),
        ('share/' + package_name, ['package.xml']),
        (os.path.join('share', package_name, 'launch'),
         glob(os.path.join('launch', '*launch.[pxy][yma]*'))),
        (os.path.join('share', package_name, 'config'),   # add this line
         glob(os.path.join('config', '*.yaml'))),
    ],
```

## Step 3 — Load the File in the Launch File

Edit `launch/turtlesim.launch.py`. Find the package share directory at launch time with `get_package_share_directory`, and replace both inline `parameters` dicts with the file:

```python
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    config = os.path.join(
        get_package_share_directory('turtlesim_controller'),
        'config',
        'circles.yaml',
    )

    turtlesim_node = Node(
        package='turtlesim',
        executable='turtlesim_node',
        name='turtlesim',
        output='screen',
    )

    circle_turtle1 = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
        parameters=[config],
    )

    circle_turtle2 = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        namespace='turtle2',
        output='screen',
        parameters=[config],
        remappings=[('turtle1/cmd_vel', '/turtle2/cmd_vel')],
    )

    return LaunchDescription([
        turtlesim_node,
        circle_turtle1,
        circle_turtle2,
    ])
```

A plain string path in the `parameters` list is treated as a YAML file. Both nodes receive the **same file**; each one picks out the entry whose key matches its own fully-qualified name.

Rebuild (new files must be reinstalled), source, and launch:

```bash
cd ~/tutorial_ws
colcon build --packages-select turtlesim_controller
source ~/tutorial_ws/install/setup.bash
ros2 launch turtlesim_controller turtlesim.launch.py
```

In a second terminal:

```bash
ros2 param get /circle_publisher radius           # Double value is: 3.0
ros2 param get /turtle2/circle_publisher radius   # Double value is: 1.0
```

Look at the file that was actually loaded. It lives in `install/`, not in `src/`:

```bash
ls ~/tutorial_ws/install/turtlesim_controller/share/turtlesim_controller/config
# circles.yaml
```

**Editing `src/.../circles.yaml` has no effect until you rebuild**, unless you build with `colcon build --symlink-install`, which links to the source file instead of copying it.

## Exercise

**Description**

Make the parameter file share defaults using a wildcard. Change `circles.yaml` so that:

- A `/**` entry sets `angular_speed: 2.0` for every node
- `circle_publisher` overrides only `radius: 3.0`
- `/turtle2/circle_publisher` overrides only `radius: 1.0`

**Requirements**

- `ros2 param get /circle_publisher angular_speed` returns `2.0`
- `ros2 param get /turtle2/circle_publisher angular_speed` returns `2.0`
- `ros2 param get /circle_publisher radius` returns `3.0`; the turtle2 node returns `1.0`

---

## Answer Key

```yaml
/**:
  ros__parameters:
    angular_speed: 2.0

circle_publisher:
  ros__parameters:
    radius: 3.0

/turtle2/circle_publisher:
  ros__parameters:
    radius: 1.0
```

Rebuild and relaunch. `/**` matches both nodes, so both get `angular_speed: 2.0`. The specific entries add `radius` for one node each. Nodes that do not declare a parameter (such as `/turtlesim`, which has no `angular_speed`) ignore entries for it.

---

## Summary

| Concept | Key point |
|---|---|
| Structure | `node_name:` → `ros__parameters:` → `param: value` |
| Node key | Plain name for no namespace; `/ns/name` for a namespaced node; `/**` for every node |
| Loading | Put the file path in `parameters=[...]` |
| Installing | Add `config/*.yaml` to `data_files`; rebuild after editing (or use `--symlink-install`) |
| Types | YAML types must match the declared parameter types |
