## Why Launch Files?

Through Module 3 you have been starting nodes one terminal at a time:

```bash
# Terminal 1
ros2 run turtlesim turtlesim_node

# Terminal 2
ros2 run goal_point_publisher goal_point_publisher

# Terminal 3
ros2 run turtlesim_controller turtle_lf_controller

# Terminal 4
ros2 lifecycle set /turtle_lf_controller configure
ros2 lifecycle set /turtle_lf_controller activate
```

This works for development but breaks down quickly: the order matters, steps get missed, and sharing a reproducible setup with someone else means sending a list of commands and hoping they run them in the right order.

A **launch file** is a Python script that describes the entire system in one place. Instead of four terminals and six commands, you run one:

```bash
ros2 launch turtlesim_controller my_system.launch.py
```

Launch files also give you parameter configuration, namespace management, event-driven coordination, and automated lifecycle transitions — all covered in the sections ahead.

---

## The Minimum Launch File

A ROS2 launch file is a plain Python file whose name ends in `.launch.py`. It must contain a function called `generate_launch_description()` that returns a `LaunchDescription` object.

```python
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(
            package='turtlesim',
            executable='turtlesim_node',
        ),
    ])
```

`LaunchDescription` takes a list of **actions** — things to do when the launch file runs. `Node` is the most common action: it starts a ROS2 node by package name and executable name. Those two arguments are the only required ones.

### The `Node` action

```python
Node(
    package='...',        # ROS2 package name
    executable='...',     # entry point name from setup.py console_scripts
    name='...',           # optional: override the node name
    output='screen',      # optional: print stdout/stderr to terminal
)
```

Without `output='screen'`, node output is suppressed. Include it while developing so you can see log messages.

## Step 2 — Write the Launch File

Create `~/tutorial_ws/src/turtlesim_controller/launch/turtlesim.launch.py`:

```python
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    turtlesim_node = Node(
        package='turtlesim',
        executable='turtlesim_node',
        name='turtlesim',
        output='screen',
    )

    return LaunchDescription([
        turtlesim_node,
    ])
```

## Step 3 — Register the Launch Directory in `setup.py`

Launch files are installed as package share data — not Python modules. You must add an entry to `data_files` in `setup.py` so `colcon build` installs them.

Open `~/tutorial_ws/src/turtlesim_controller/setup.py`. Add the `os` and `glob` imports at the top, and one new line in `data_files`:

```python
import os
from glob import glob
from setuptools import find_packages, setup

package_name = 'turtlesim_controller'

setup(
    name=package_name,
    ...
    data_files=[
        ('share/ament_index/resource_index/packages',
            ['resource/' + package_name]),
        ('share/' + package_name, ['package.xml']),
        (os.path.join('share', package_name, 'launch'),   # add this line
         glob(os.path.join('launch', '*launch.[pxy][yma]*'))),
    ],
    ...
)
```

The glob pattern `*launch.[pxy][yma]*` matches files whose extension includes `.py`, `.xml`, and `.yaml` — covering all ROS2 launch file formats. Every `.launch.py` file you add to `launch/` will be picked up automatically.

## Step 4 — Build and Run

```bash
cd ~/tutorial_ws
colcon build --packages-select turtlesim_controller
source ~/tutorial_ws/install/setup.bash
```

Launch the file:

```bash
ros2 launch turtlesim_controller turtlesim.launch.py
```

The turtlesim window opens. Press `Ctrl+C` to stop all launched processes — the launch system handles cleanup automatically.

To list all available launch files in a package:

```bash
ros2 launch turtlesim_controller --list-files
```

## Answer Key

```python
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    turtlesim_node = Node(
        package='turtlesim',
        executable='turtlesim_node',
        name='turtlesim',
        output='screen',
    )

    circle_publisher_node = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
    )

    return LaunchDescription([
        turtlesim_node,
        circle_publisher_node,
    ])
```

Both nodes are independent `Node` actions in the same `LaunchDescription` list. The launch system starts them in sequence, but because ROS2 initialisation is asynchronous, you should not assume one is fully ready before the other starts communicating.

`circle_publisher` starts publishing `cmd_vel` immediately — the turtle begins drawing circles as soon as both nodes are running. No extra configuration steps are needed.

## Summary

| Concept | Key point |
|---|---|
| `.launch.py` naming | All launch files must end in `.launch.py` |
| `generate_launch_description()` | The required entry point — must return a `LaunchDescription` |
| `LaunchDescription([...])` | Takes a list of actions to execute |
| `Node(package, executable)` | Starts a ROS2 node; `name` and `output` are optional but useful |
| `output='screen'` | Without this, node stdout/stderr is suppressed |
| `data_files` glob | Installs every `*.launch.py` in `launch/`; required for `ros2 launch` to find the file |
| `ros2 launch <pkg> <file>` | Starts all nodes in the launch file |
| `ros2 launch <pkg> --list-files` | Lists all available launch files in a package |
| `Ctrl+C` in the launch terminal | Stops all processes started by the launch file |
