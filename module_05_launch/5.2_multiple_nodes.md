# 5.2 — Multiple Nodes: Namespaces, Remapping, Parameters

## Learning Objectives

By the end of this section, you will be able to:
- Pass parameter values to a node at launch time using `parameters=[{...}]`
- Use `namespace` to prefix all of a node's relative names, and predict the resulting topic names
- Use `remappings` to rewire specific topic names without changing the node's source code
- Diagnose and fix a namespace that breaks a connection

## How Names Are Resolved

Run the launch file from 5.1 and list the topics:

```bash
ros2 launch turtlesim_controller turtlesim.launch.py
```

```bash
ros2 topic list
# /parameter_events
# /rosout
# /turtle1/cmd_vel
# /turtle1/color_sensor
# /turtle1/pose
```

The turtle draws circles. Both `turtlesim_node` and `circle_publisher` use the **relative** name `turtle1/cmd_vel`. With no namespace, a relative name resolves to `/turtle1/cmd_vel`, so the two nodes meet on the same topic.

The relative name is the key: ROS 2 puts the node's **namespace** in front of every relative name. Absolute names (leading `/`) are left alone.

## Concept: Inline Parameters

The `Node` action accepts a `parameters` argument — a list whose elements are either dicts (inline values) or `ParameterFile` objects (covered in 5.3). For now, use a dict:

```python
Node(
    package='turtlesim_controller',
    executable='circle_publisher',
    name='circle_publisher',
    output='screen',
    parameters=[{'radius': 3.0, 'angular_speed': 1.5}],
)
```

- Dict keys are parameter names as declared with `declare_parameter` in the node
- Values are Python literals: `float`, `int`, `bool`, or `str`
- These values override the node's defaults; they take effect when the node starts
- The list can contain multiple dicts; later entries override earlier ones for the same key

Verify after launch:

```bash
ros2 param get /circle_publisher radius
# Double value is: 3.0
```

## Concept: Namespace

`namespace='...'` on a `Node` action prefixes every relative name that node uses — its own name, its topics, services, and parameters:

```python
Node(
    package='turtlesim_controller',
    executable='circle_publisher',
    name='circle_publisher',
    namespace='robot',
    output='screen',
)
```

| Without namespace | With `namespace='robot'` |
|---|---|
| Node: `/circle_publisher` | Node: `/robot/circle_publisher` |
| Topic: `/turtle1/cmd_vel` | Topic: `/robot/turtle1/cmd_vel` |
| `ros2 param get /circle_publisher radius` | `ros2 param get /robot/circle_publisher radius` |

Namespaces are meant to move a **whole group** of nodes together, for example one namespace per robot. Applied to a single node in a group that shares topics, a namespace disconnects it: `circle_publisher` would publish on `/robot/turtle1/cmd_vel` while turtlesim still listens on `/turtle1/cmd_vel`.

---

## Concept: Remappings

`remappings` is a list of `(from, to)` tuples. Each pair renames one topic or service for that node, without changing its source code:

```python
Node(
    package='turtlesim_controller',
    executable='circle_publisher',
    namespace='robot',
    output='screen',
    remappings=[
        ('turtle1/cmd_vel', '/turtle1/cmd_vel'),
    ],
)
```

- A relative `from` is expanded with the node's namespace first, so `turtle1/cmd_vel` matches the node's `/robot/turtle1/cmd_vel`
- An absolute `to` (leading `/`) is used exactly as written and is not prefixed by the namespace

| Approach | Best for |
|---|---|
| `namespace` | Moving a whole group of nodes under one prefix |
| `remappings` | Rewiring one or two specific topics, including reconnecting a node whose names do not match |
| Both together | Namespace the node, then remap the topics that must stay shared |

## Step 1 — Add Inline Parameters

Open `~/tutorial_ws/src/turtlesim_controller/launch/turtlesim.launch.py` and add `parameters` to `circle_publisher`:

```python
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    turtlesim_node = Node(
        package='turtlesim',
        executable='turtlesim_node',
        name='turtlesim',
        output='screen',
    )

    circle_publisher_node = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
        parameters=[{'radius': 3.0, 'angular_speed': 1.5}],
    )

    return LaunchDescription([
        turtlesim_node,
        circle_publisher_node,
    ])
```

Rebuild, source, and launch:

```bash
cd ~/tutorial_ws
colcon build --packages-select turtlesim_controller
source ~/tutorial_ws/install/setup.bash
ros2 launch turtlesim_controller turtlesim.launch.py
```

In a second terminal:

```bash
ros2 param get /circle_publisher radius
# Double value is: 3.0

ros2 param get /circle_publisher angular_speed
# Double value is: 1.5
```

Kill the launch (`Ctrl+C`).

## Step 2 — Break It with a Namespace

Add `namespace='robot'` to the `circle_publisher` action, leaving everything else unchanged:

```python
    circle_publisher_node = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        namespace='robot',
        output='screen',
        parameters=[{'radius': 3.0, 'angular_speed': 1.5}],
    )
```

Rebuild, source, and launch. The turtle does **not** move. Inspect why:

```bash
ros2 node list
# /robot/circle_publisher
# /turtlesim
```

```bash
ros2 topic list
# ...
# /robot/turtle1/cmd_vel
# /turtle1/cmd_vel
# ...
```

```bash
ros2 topic info /turtle1/cmd_vel
# Publisher count: 0
# Subscription count: 1
```

The publisher is on `/robot/turtle1/cmd_vel`, the turtle listens on `/turtle1/cmd_vel`. Note that the parameters now live at `/robot/circle_publisher`. Kill the launch (`Ctrl+C`).

---

## Step 3 — Fix It with a Remapping

Add a remapping that sends the publisher back to the shared topic:

```python
    circle_publisher_node = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        namespace='robot',
        output='screen',
        parameters=[{'radius': 3.0, 'angular_speed': 1.5}],
        remappings=[('turtle1/cmd_vel', '/turtle1/cmd_vel')],
    )
```

Rebuild, source, and launch. The turtle draws circles again, and:

```bash
ros2 node list
# /robot/circle_publisher
# /turtlesim

ros2 topic info /turtle1/cmd_vel
# Publisher count: 1
# Subscription count: 1

ros2 param get /robot/circle_publisher radius
# Double value is: 3.0
```

The node keeps its isolated name and parameters, while one topic is bridged to the shared system. Remove `namespace='robot'` (keep the parameters) before the exercise. Kill the launch (`Ctrl+C`).

## Exercise

**Description**

Add a second `circle_publisher` to `turtlesim.launch.py` under `namespace='turtle2'` with `radius=1.0` and `angular_speed=3.0`, publishing to `/turtle2/cmd_vel`. Both `circle_publisher` instances should run simultaneously from a single `ros2 launch` command.

**Requirements**

- `ros2 topic list` shows both `/turtle1/cmd_vel` and `/turtle2/cmd_vel`
- `ros2 node list` shows `/circle_publisher` and `/turtle2/circle_publisher`
- `ros2 param get /turtle2/circle_publisher radius` returns `1.0`
- `ros2 param get /circle_publisher radius` still returns `3.0`

Note: turtlesim has only one turtle (`turtle1`) by default, so nothing subscribes to `/turtle2/cmd_vel`. That is expected — this exercise demonstrates namespaces and remapping, not multi-turtle control.

---

## Answer Key

```python
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    turtlesim_node = Node(
        package='turtlesim',
        executable='turtlesim_node',
        name='turtlesim',
        output='screen',
    )

    circle_turtle1 = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        output='screen',
        parameters=[{'radius': 3.0, 'angular_speed': 1.5}],
    )

    circle_turtle2 = Node(
        package='turtlesim_controller',
        executable='circle_publisher',
        name='circle_publisher',
        namespace='turtle2',
        output='screen',
        parameters=[{'radius': 1.0, 'angular_speed': 3.0}],
        remappings=[('turtle1/cmd_vel', '/turtle2/cmd_vel')],
    )

    return LaunchDescription([
        turtlesim_node,
        circle_turtle1,
        circle_turtle2,
    ])
```

The two `Node` actions share the same `name` and `executable`. Without the namespace, they would collide on `/circle_publisher`. With `namespace='turtle2'`, the second is `/turtle2/circle_publisher`, so the names are distinct and each node has its own parameter store. The remapping then points its publisher at `/turtle2/cmd_vel` instead of the default `/turtle2/turtle1/cmd_vel`.

```bash
ros2 param get /circle_publisher radius           # 3.0
ros2 param get /turtle2/circle_publisher radius   # 1.0
```

## Summary

| `Node` argument | Type | Effect |
|---|---|---|
| `namespace='...'` | `str` | Prefixes all relative names (node name, topics, services, params) |
| `parameters=[{'key': value}]` | `list` of `dict` | Overrides `declare_parameter` defaults at launch |
| `remappings=[('from', 'to')]` | `list` of `tuple` | Rewires specific topic/service names; absolute `to` is not prefixed |
| `name='...'` | `str` | Sets the node's base name before namespace qualification |
